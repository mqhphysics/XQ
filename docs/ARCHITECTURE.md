# 晓球（XiaoQiu）微信小程序架构设计文档

## 1. 项目概述

「晓球」是面向高校校园足球赛事的综合服务小程序，覆盖赛事资讯、赛程与实时战报、积分与球员数据统计、主队关注、球员与用户主页、校园足球社区互动、队长球队管理以及赛事信息员快捷录报等核心场景。

### 1.1 设计目标
- **关注点分离（Separation of Concerns）**：严格划分视图层（Pages & Components）、状态层（Store）、领域服务与网络通信层（Services），确保单一职责与单向数据流。
- **高响应体验**：针对校园球场弱网及高频切换场景，采用「内存态缓存 + 本地持久化缓存 + 后台静默刷新（Stale-While-Revalidate）」策略，消除页面白屏与导航卡顿。
- **包体积受控**：静态大图与业务媒体全部通过云端媒体网关按需加载，本地仅打包矢量图标与核心样式，确保主包体积严格控制在微信小程序限制之内。
- **类型安全**：全链路基于 TypeScript 严格模式开发，接口契约、视图状态与路由参数均具备显式类型定义。

## 2. 技术栈与运行环境

| 层级 | 选型 | 说明 |
| :--- | :--- | :--- |
| 应用框架 | Taro 4 + React 18 | 采用 Functional Components 与 Hooks 编写视图与状态逻辑 |
| 开发语言 | TypeScript 5（Strict） | 全量静态类型检查，编译期拦截契约不一致问题 |
| 样式体系 | SCSS + Design Tokens | 基于 `750rpx` 基准画布，统一色板、字号梯度、圆角与阴影变量 |
| 网络通信 | 微信云托管 `callContainer` / HTTPS | 生产环境经微信云托管容器网关转发，本地调试支持直连 API |
| 状态管理 | 轻量级响应式 Store + React Context | 管理会话态、当前赛事上下文、主队偏好及跨页事件同步 |

```text
XQ/

├─ docs/                    # 架构设计、接口契约与工程规范文档

│  ├─ app.config.ts         # 全局路由注册表与窗口表现配置

│  ├─ types/                # 领域模型与后端 API DTO 类型定义
│  ├─ services/             # 网络通信与领域接口层
│  │  ├─ client.ts          # 统一请求内核（云托管/HTTP 适配、鉴权注入、异常归一、媒体 URL 解析）

│  ├─ store/                # 全局与跨页状态管理
│  │  ├─ session.ts         # 登录态、当前用户身份（学生/球员/队长/信息员/运营）与权限判定
│  │  ├─ competition.ts     # 当前激活赛季、赛事（男足/女足/各杯赛）与全局筛选偏好
│  │  └─ primary-team.ts    # 用户主队绑定状态与跨页同步通知
│  ├─ components/           # 跨页面复用组件
│  │  ├─ app-shell/         # 自定义顶部导航栏、底部常驻 Tab 栏（含主队动效）、页面容器

│  │  ├─ match-card/        # 通用比赛卡片（未开赛 / 进行中 / 已完赛 / 官方判罚态）
│  │  ├─ pitch-board/       # 105:68 标准比例球场组件（支持只读展示与队长拖拽布阵）
│  │  ├─ post-card/         # 社区帖子与比赛快报卡片组件
│  │  ├─ image-cropper/     # 固定比例（2.8:1 封面 / 1:1 头像队徽）图片裁剪弹窗
│  │  └─ modal-sheet/       # 统一顶栏固定、内容区滚动的弹窗容器
│  └─ pages/                # 页面视图层（与路由表一一对应）
└─ AGENTS.md                # 工程开发规范与协作约束
```

### 3.1 依赖方向约束
遵循严格的单向依赖原则：
`pages` → `components` / `store` → `services` → `types`
- `components/` 仅接收 Props 渲染 UI 并通过回调抛出事件，不直接耦合特定页面路由。
- `services/` 负责与后端交互及数据格式归一化，不依赖任何 React 组件或页面状态。
- 所有模块间引用统一使用 `@/` 路径别名，禁止超过两级的相对路径（如 `../../..`）。

## 4. 路由规划与页面体系

小程序采用自定义导航栏（`navigationStyle: 'custom'`），页面划分为三大层级：

### 4.1 一级主导航页（底部常驻 5 Tab）
1. **首页（`pages/home/index`）**
   - 顶部赛事切换器、赛事轮播公告、平台通知条、最新比赛快报与校园足球社区动态流、发帖悬浮入口。
2. **赛程（`pages/schedule/index`）**
   - 按比赛日吸顶分组展示赛程列表；支持按阶段、小组、球队及「只看主队」合一筛选；展示实时比分或完赛结果；提供跳往数据中心对阵图的快捷入口。
3. **主队（`pages/my-team/index`）**
   - 展示用户设定的主队封面（2.8:1）、队徽、口号、近期比赛、积分排名与完整球员名单；支持切换或重设主队并触发主队导航动效。
4. **数据（`pages/data-center/index`）**
   - 小组赛积分榜（A/B/C/D 组）、淘汰赛晋级对阵图、球员数据榜（射手榜、助攻榜、黄牌/红牌榜）。
5. **我的（`pages/me/index`）**
   - 个人封面（2.8:1）与资料卡片、身份标签（球员 / 队长 / 信息管理员 / 网站运营）、我的收藏、消息与私聊入口、队长管理球队入口、信息员比赛录入入口及账号设置。

### 4.2 二级详情与浏览页
6. **比赛详情（`pages/match-detail/index`）**：赛事信息与比分头部、双方首发球场图与替补席名单、中央时间轴事件流（进球、点球、乌龙、换人、红黄牌、事件 GIF 上传与预览）、本场快报卡片、赛况讨论评论区。
7. **球队详情（`pages/team-detail/index`）**：任意球队的背景封面、队徽、历史战绩、赛程与球员大名单。
8. **球员详情（`pages/player-detail/index`）**：球员技术档案、赛季出场/进球/助攻/红黄牌统计及所属球队履历。
9. **用户主页（`pages/person-detail/index`）**：社区用户个人主页、发帖动态与发起私聊入口。
10. **帖子/快报详情（`pages/post-detail/index`）**：快报或社区帖正文、多图预览、点赞收藏、评论列表与带图评论发布、右上角 `⋯` 投诉菜单。

### 4.3 鉴权、互动与角色工作台页
11. **登录与注册（`pages/login/index`）**：学号/账号密码登录、新生按姓名注册与学号绑定提交、游客浏览引导。
12. **发布动态（`pages/compose/index`）**：图文帖子编辑、关联比赛或球队标签、图片上传。
13. **消息中心（`pages/messages/index`）**：互动通知与用户一对一私聊会话。
14. **我的收藏（`pages/favorites/index`）**：收藏的比赛快报与社区帖列表。
15. **球队管理工作台（`pages/team-manage/index`）**：队长专属——修改队徽与球队背景、编辑口号、105:68 球场拖拽排布首发阵容、大名单球员审核与邀请。
16. **比赛快捷录入（`pages/quick-report/index`）**：信息管理员专属——选择待录入/进行中比赛，实时录入比分、首发、换人、进球与红黄牌事件。

## 5. 核心领域与技术机制设计

### 5.1 网络通信层（`services/client.ts`）
- **双通道自适应**：小程序环境优先初始化微信云托管并调用 `wx.cloud.callContainer`，携带目标服务名与请求头；开发环境支持回退至 `Taro.request` 直连后端网关。
- **鉴权与会话拦截**：自动从 `store/session` 读取 Bearer Token 注入请求头；遇到 `401 Unauthorized` 时自动清理失效会话并通知视图层平顺降级为游客态或引导登录。
- **媒体地址解析（`resolveMediaUrl`）**：后端返回的相对媒体路径（如 `/api/media/...`）统一通过媒体域名拼接为完整可访问的 HTTPS URL，杜绝组件内硬编码域名。

### 5.2 状态与缓存策略（`store/`）
- **赛事上下文同步**：用户在首页或赛程页切换赛事（如「2026 新生杯男足」切换至「2026 新生杯女足」）时，写入 `store/competition` 并持久化至 Storage，赛程页与数据中心自动响应同一赛事上下文。
- **页面秒开体验**：核心列表接口（首页、赛程、积分榜）在内存中维护带时间戳的快照；切页时立即渲染已有快照，同时在后台发起静默更新，数据变化时无感刷新视图。

### 5.3 视觉与几何比例规范
- **背景封面统一比例**：个人背景与球队背景在上传裁剪、后端存储及前端展示全链路固定为 **`2.8:1`（`2240×800`）**，完整展示不裁切、不使用模糊边填充；覆于背景之上的文字与数据块统一配置半透明浅白底衬以保证可读性。
- **队徽一致性**：真实队徽与未定/默认占位队徽保持严格一致的圆形尺寸与透明通道。
- **球场标准比例**：首发阵容球场严格锁定 **`105:68`（约 `1.54:1`）** 真实足球场比例，球员节点基于归一化坐标定位在边线内部，绝不随外层容器拉伸变形。

## 6. 三日开发推进计划（3-Day Roadmap）

按「基础设施 → 核心只读闭环 → 深度业务详情 → 互动与角色工作台」的工程依赖顺序，分为三天完成：

### Day 1：工程基建、网络网关与核心赛事浏览闭环
- **上午（基建与外壳）**
  - 完成工程配置、全局设计变量（`styles/variables.scss`）、类型契约（`types/`）与路由表（`app.config.ts`）。
  - 实现 `services/client.ts`（云托管双通道请求器、错误处理、媒体 URL 解析）与 `store/`（会话、赛事上下文、主队状态）。
  - 实现 `components/app-shell`（自定义顶栏、底部 5 Tab 导航栏及主队切换过渡动效）。
- **下午（登录与首页）**
  - 实现 `pages/login`（登录、注册、游客进入）。
  - 实现 `pages/home`（赛事切换、轮播公告、平台通知条、快报与社区信息流）。
- **晚上（赛程中心）**
  - 实现 `pages/schedule`（日期吸顶列表、阶段/球队/主队合一筛选器、比赛卡片各状态渲染）。
  - **Day 1 里程碑**：小程序可登录、可切换赛事、可完整浏览首页公告快报与全部赛程。

### Day 2：比赛深度体验、数据中心与主队体系
- **上午（比赛详情页）**
  - 实现 `components/pitch-board`（105:68 标准球场组件）与中央时间轴组件（进球、换人上下箭头、红黄牌、事件 GIF 展示与上传）。
  - 完成 `pages/match-detail`（比分头部、首发与替补阵容、时间轴、本场快报卡片、赛况评论区）。
- **下午（数据中心）**
  - 实现 `pages/data-center`（小组赛积分榜、淘汰赛晋级对阵图、射手/助攻/红黄牌榜）。
- **晚上（主队与球队/球员档案）**
  - 实现 `pages/my-team`、`pages/team-detail` 与 `pages/player-detail`，打通从赛程、榜单、阵容图点击跳转球队与球员档案的完整链路。
  - **Day 2 里程碑**：赛事核心体验（看赛程 → 看比赛首发与时间轴 → 查积分射手榜 → 追主队与球员数据）全面跑通。

### Day 3：社区互动、个人中心与角色工作台（队长 & 信息员）
- **上午（社区与消息闭环）**
  - 实现 `pages/post-detail`（快报/帖子详情、带图评论、右上角投诉菜单）、`pages/compose`（发帖与配图上传）、`pages/person-detail`（用户主页）、`pages/messages`（私聊与通知）及 `pages/favorites`（收藏夹）。
- **下午（个人中心与角色工作台）**
  - 实现 `pages/me`（个人资料、2.8:1 封面裁剪上传、身份面板路由）。
  - 实现 `pages/team-manage`（队长编辑球队资料、拖拽排布首发与替补、管理大名单）与 `pages/quick-report`（信息管理员实时/赛后录入比分与事件）。
- **晚上（全链路联调、体积审计与发布）**
  - 全量 TypeScript 类型检查、主包体积审计（确保 < 2MB）、真机预览验收并生成正式发布包。
  - **Day 3 里程碑**：全功能闭环交付，达到正式上线标准。
