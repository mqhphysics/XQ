- 当前：0.8.7 已上传微信开发版，配套 API 沿用已部署的 0.8.5。本轮修改限于小程序界面及读取逻辑，API 和数据库结构未变。微信审核与正式发布未操作；各版本完整工程独立放在 `XQ-work/releases/版本号`，旧版保留。

- 比赛评论输入改为打卡，复用已有打卡设计；原有星级评分保留。打卡采用独立记录和幂等接口，不把打卡算成五星、不伪造人数，也不声称核验了地理到场。

## 目录

```text
XQ/
  apps/weapp/          微信小程序
  apps/web/            电脑用户网站
  apps/admin-web/      电脑管理平台
  apps/api/            NestJS API
  apps/worker/         异步处理
  packages/            契约、生成客户端、领域工具和设计变量
  prisma/              数据模型与完整迁移
  infra/               部署配置
  scripts/             当前正式命令
```

旁边的 `XQ-data` 用于业务媒体和私有配置，`XQ-work` 用于本地候选、日志和测试临时文件。两者不纳入 Git。原 `xiaoqiu` 保持原样，仅作来源与回退对照，没有把它的分支、worktree、历史报告或私人资料复制进来。

平台页面和样式分开，已有公共契约继续复用；部分默认文件承担 TypeScript 类型入口，不能仅因为存在平台同名文件就删除。第一轮不机械重写这些兼容边界。

## 小程序使用

1. 登录后可查看与账号关联的球队、收藏和通知；游客可以浏览已公开内容。
2. 首页查看公告、战报和比赛入口，也可以搜索球员、球队、比赛及官方内容。普通用户不再有发动态入口。
3. 打开比赛后，在“比赛评分、比赛事件、首发阵容”之间点击或横向滑动切换。已结束比赛可确认一次星级评分；打卡需要登录，同一账号同场比赛重复点击不会重复计数。
4. 登录后打开含片段的比赛，GIF 提前下载；完整文件的字节数、帧数和时长校验通过后才自动播放，加载期间显示封面。GIF 保持原始比例、完整时长和无限循环；大图及全屏复用同一文件。缓存保留三天，退出比赛和重新加载后继续复用，片段更新或缓存过期再下载；失败可重试，自动播放设置可主动关闭。
5. 从“我的主队”进入球队及管理入口。大名单锁定后按已审核结果展示；头像为空时显示姓名最后一个字。未入选成员以文字区分，继续保留成员管理能力。可编辑阶段通过“加入／移出”调整选择，再保存或提交审核；已锁定名单不能绕过管理审核。
6. “阵容”可选择已保存计划、修改站位、保存或设为默认。系统默认名称简化为“默认阵容”，已有自定义名称保留。正式赛前确认与私人战术草稿仍然分开。
7. 消息中心保留系统、回复、提及和点赞等通知，支持标记已读和打开关联内容；私信入口已退出。个人资料中的昵称、头像、背景和简介按原入口编辑；官方发布在管理平台完成。
8. 更换头像时先选图、手动拖动和缩放裁切，再点保存；界面展示处理和上传状态，失败后可重试。关联球员沿用账号头像时同步更新，独立上传的球员照片保留。
9. 关注管理中按住拖动柄排序，中间项目可以放到最前或最后，贴近列表上下边缘时自动滚动。球员与球队均显示图片，缺少球员图片时使用姓名最后一字。
10. “我的身份”展示球员摘要及主页入口，身份关联在“身份管理”操作。信息管理员同一行显示完整赛事名称和选择框，先显示三场紧凑比赛，开始状态放右侧；“展开全部”有边框、箭头和展开/收起状态。下方直接显示质量分与已录入场次。“评分说明”逐项列出真实规则，绿色加分、红色扣分。
11. 数据页“对阵”直接从晋级图开始，图区域使用边到边的浅色背景，左侧阶段名与右侧比赛中线对齐。锁定名次的队伍填入签位，其余只显示“待定”。八强按 A1–B2、C1–D2、B1–A2、D1–C2，同组分处两个半区；四队、八队的连线及对称结构保留。正式比赛保留真实 ID、队伍和成绩，未发布比赛保持只读，季军赛独立展示。女足当前四组各第一名晋级四强。
12. 申请加入球队时，“位置”与选择框在同一行；下方留言为单行、居中的选填输入框，保留清楚的上下间距。所有入口复用同一份申请表单。
13. 头像侧栏底部按钮上方、“我的”退出登录按钮下方，各有一行“晓球网站：xiaoqiu-beta.pages.dev”。点击整行即可复制完整的 `https://xiaoqiu-beta.pages.dev/`，可粘贴到浏览器打开。右侧单独的复制按钮已去除；当前个人主体小程序继续采用复制方式。
14. 球员详情页五条能力条下方，在至少三项能力已填写时显示雷达图。图中只包含已填能力，0 分也算已填；未填项不按 0 分计算。三、四、五项分别绘制对应维度的图，全部未填或仅填一两项时不显示。自己保存自评、后台编辑已有评分字段后，刷新球员资料即可展示对应数值。

### 0.8.7 侧栏与能力图收尾

- 侧栏保留原有资料和身份卡。信封右移，并按实际胶囊位置保留安全间距；基本信息按内容排布，收紧分隔线上方留白。主队显示为“我的主队 · 名称”一行，长名称截断，不再展示关注数量。身份区域改为普通内容，常规资料不会滚动；只有整个内容区放不下时才统一滚动，底部网址和按钮保持可用。
- 打开侧栏时复用当前账号的已有缓存，球队与球员资料分别读取，单项慢或失败时其它内容继续展示。数据按账号和组织核对，沿用原有刷新规则。能力权限接口只合并同账号、组织及会话的并发请求，完成后不缓存权限结果；各调用者收到独立对象，错误后可重试，旧请求不会清掉新账号的在途任务。
- 雷达图仅放在球员详情的五条能力条下方，保留原有条形图。使用已有五项评分字段，后台对应编辑入口和 API 字段继续使用；未增加新图表库、接口或数据表。几何按真实尺寸计算，数据变化或显示尺寸变化时重绘，隐藏页暂停绘制，不设置动画循环。
- 开发验收曾发现可见的原生 Canvas 穿透到侧栏，已改为屏幕外绘制、普通 PNG 图片展示。PNG 使用内存 data URI，不生成临时图片文件；侧栏只显示原来的资料内容。
