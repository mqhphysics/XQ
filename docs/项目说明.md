# 晓球 XQ 项目说明

本文件是唯一的正式项目说明，直接更新，不新增轮次报告或多层文档目录。

## 当前版本和范围

- 来源：原晓球主仓 `1ee7157`，整合了 0.7.11。它相对上次检查的 `39822c9` 涉及 100 个文件、8,044 行新增和 1,931 行删除，并非仅整理文件名。
- 当前：0.8.0 已上传微信开发版，配套 API 和打卡数据库迁移已经部署。尚未提交微信平台审核或正式上线。网站、后台和 Worker 的运行版本保持原状。
- 微信是核心，网站保留并独立维护，管理平台只做电脑端；第一轮保持认可的页面结构、颜色、手势、昵称、头像、阵容、赛果、公告和战报。
- 退出普通用户发帖、评论、转发和私信。消息中心移除私信选项，保留系统、回复、提及和点赞等通知；点赞、收藏、反馈、官方发布与授权人员比赛录入保留。历史内容不删除。
- 比赛评论输入改为打卡，复用已有打卡设计；原有星级评分保留。打卡采用独立记录和幂等接口，不把打卡算成五星、不伪造人数，也不声称核验了地理到场。

平台页面和样式分开，已有公共契约继续复用；部分默认文件承担 TypeScript 类型入口，不能仅因为存在平台同名文件就删除。第一轮不机械重写这些兼容边界。

## 小程序使用

1. 登录后可查看与账号关联的球队、收藏和通知；游客可以浏览已公开内容。
2. 首页查看公告、战报和比赛入口，也可以搜索球员、球队、比赛及官方内容。普通用户不再有发动态入口。
3. 打开比赛后，在“比赛评分、比赛事件、首发阵容”之间点击或横向滑动切换。已结束比赛可确认一次星级评分；打卡需要登录，同一账号同场比赛重复点击不会重复计数。
4. 比赛事件中的 GIF 在进入比赛时后台预下载，滑到可见位置自动播放；点击片段可打开大图。设置中的自动播放关闭或减少动态效果仍受尊重。网络失败时可以重试。
5. 从“我的主队”进入球队及管理入口。大名单锁定后按已审核结果展示；头像为空时显示姓名最后一个字。未入选成员以文字区分，继续保留成员管理能力。可编辑阶段通过“加入／移出”调整选择，再保存或提交审核；已锁定名单不能绕过管理审核。
6. “阵容”可选择已保存计划、修改站位、保存或设为默认。系统默认名称简化为“默认阵容”，已有自定义名称保留。正式赛前确认与私人战术草稿仍然分开。
7. 消息中心保留系统、回复、提及和点赞等通知，支持标记已读和打开关联内容；私信入口已退出。个人资料中的昵称、头像、背景和简介按原入口编辑；官方发布在管理平台完成。

## 安装与运行

使用原主仓锁定依赖，不在迁移中升级框架。需要兼容的 Node.js 和 pnpm。

```powershell
pnpm install --frozen-lockfile
pnpm dev:weapp
pnpm dev:web
pnpm dev:admin
```

网站使用 3000，API 使用 3001。微信可使用 `apps/weapp/.env.beta` 中已有云通道进行本地构建；普通本地模式用 `TARO_APP_API_BASE_URL` 指向已有 API。不要为看小程序而启动 Docker。

后端运行需要真实可用的 PostgreSQL 配置。准备自己的 `DATABASE_URL` 后再执行 `pnpm dev:api`；本项目不会自动启动数据库，也不把已有数据缺失伪装成新空库。没有把旧项目真实数据库口令复制进来。本地媒体默认写到旁边的 `XQ-data/media/posts`，部署时使用明确的持久卷路径。

## 构建和本地微信检查

```powershell
pnpm --filter @xiaoqiu/weapp build:beta
pnpm --filter @xiaoqiu/weapp release:prepare
pnpm --filter @xiaoqiu/web build
pnpm --filter @xiaoqiu/admin-web build
pnpm --filter @xiaoqiu/api build
pnpm --filter @xiaoqiu/worker build
```

`release:prepare` 只制作独立完整工程，不上传。候选路径为 `D:/MuDevSpace/XQ-work/releases/0.8.0`；用微信开发者工具导入其中的 `project.config.json` 所在目录。微信 AppID 从本机私有配置读取，不提交开发者密钥或账户存储。

本次正式上传回执为 **1,958,746 字节，约 1.9 MB**，低于微信 2 MiB 主包限制。上传的是小程序编译包，不包含整个仓库、依赖安装目录、网站、后端或服务器 GIF。上传前 90 个文件逐一比对构建散列；回执和对应文件清单保存在源码外工作目录。

同一个候选检查通过后再上传，避免审核的是一份、上传的是另一份。用户已授权本轮修复与验收通过后上传 0.8.0 并推送仓库；平台开发版上传、审核和正式上线分别记录真实状态。

微信开发者工具通过官方 CLI 打开同一候选，关闭启动时恢复的旧工程窗口，完成本地验收后返回 `upload` 成功。工具用完正常关闭，不保留重复窗口或本次测试服务；开发版上传不等于平台审核通过。

## 打卡与接口配套

新 API 增加：

- `GET /api/public/matches/:matchId/check-in`：读取人数及当前账号状态。
- `PUT /api/matches/:matchId/check-in`：当前登录账号打卡，重复提交只记一次。
- Prisma 迁移 `20261104000000_match_checkins`：独立打卡表、唯一约束和组织/比赛外键，不改已有评分或正式赛果。

普通用户发帖、评论和私信的旧写入接口在新 API 返回已退出；官方内容、系统通知和个人资料接口继续使用。昵称、头像和简介没有归入此次退出范围。

**配套 API 已部署。** 当前镜像为 `xiaoqiu-api:xq-0.8.0-20261104`，配套迁移镜像为 `xiaoqiu-migration:xq-0.8.0-20261104`，打卡迁移已应用。原有服务器配置、隧道、媒体持久卷及其他服务保留；更新前完成数据库备份并校验可读取。前后对比确认原比赛比分、事件、球队与阵容公开数据一致。服务器配置目录保留原有部署配置；源码以本仓为准，实际运行版本以镜像和发布记录核对，不能假定服务器历史源码目录总与运行镜像一致。

在服务器现有 PostgreSQL 中创建独立测试库及专用角色，完成全部迁移，并通过四组真实 HTTP 验收：打卡保存与重新连接读取、六个并发重试只记一次、账号及组织隔离、退出 UGC 与保留评分、已确认阵容冻结与修订、大名单审核与事务。测试库、角色和临时容器均已删除。正式比赛只进行了读取检查，没有人为制造打卡。实际微信云通道也已经读取到真实打卡人数。

当前验证：小程序普通回归 227 项、网站 214 项、API 单元/受控 HTTP 回归 271 项、后台 40 项、Worker 21 项通过；类型检查和三端构建通过。本轮客户端及新增 API 静态检查通过，全仓既有静态规则问题未宣称全部清零。八个受保护的小程序资料、球队、阵容与样式文件逐字节保持源版本一致。新增回归检查覆盖可见 `null` 文本、GIF 下载并发／失败重试／缓存淘汰及默认阵容名称。

微信官方自动化已在同一真实工程验收：打卡云通道读取、GIF 使用本地预下载文件、时间线按当前内容高度收敛、详情页取消额外底栏留白、锁定名单只保留一个头像及默认阵容精简文案。实际测得头像约 37px；当前赛事的默认计划显示“默认阵容”。浏览器自动启动失败仍不计作网站界面验收，手机真机与所有历史功能的穷举验收不作保证。

两段线上展示 GIF 从 4,452,593／4,388,883 字节优化为 1,227,469／1,089,514 字节，总量减少约 73.8%，采用 320×180 手机显示尺寸；86／70 帧、14.34／11.67 秒及循环信息均保留，原件可恢复。同步更新媒体尺寸、校验和、版本与审计记录，并核对公开接口返回字节一致。首次速度仍受网络影响，进入比赛后的提前下载及可见时播放用于降低等待。

外层旧备份与审查已清理：备份中 384 个文件已有可恢复版本，14 个独有文件核对后收在 `XQ-work/round1/recovered-backup`，不纳入正式源码。原有旧 XQ 检查点也保留在 Git 标签中。

## 契约与维护

后续优化只按当前版本复核：缓存失效范围、长场次计数和后台重复读取。10 月 25 日针对旧独立工程的审查结论不作为当前缺陷清单，旧的包体估算尤其不能替代微信实际包分析。

DTO 是 API 源，生成客户端不手改。API 构建后可执行：

```powershell
node scripts/export-openapi.mjs
node scripts/generate-api-client.mjs
```

机器契约快照放在 `packages/api-client/openapi.json`，不另建文档树。导出只读取编译后的 Nest 元数据，不启动服务或连接数据库。

日常只使用 `main`，每轮检查后本地提交；不创建额外 worktree。原 XQ 的迁移前状态由 `before-round1-20261104` 标签保存。不会为每次检查复制一套完整依赖；迁移暂存验证后清理，重要业务数据与可重建产物分开保留。
