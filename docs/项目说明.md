## 小程序使用

1. 登录后可查看与账号关联的球队、收藏和通知；游客可以浏览已公开内容。
2. 首页查看公告、战报和比赛入口，也可以搜索球员、球队、比赛及官方内容。普通用户不再有发动态入口。
3. 打开比赛后，在“比赛评分、比赛事件、首发阵容”之间点击或横向滑动切换。已结束比赛可确认一次星级评分；打卡需要登录，同一账号同场比赛重复点击不会重复计数。
4. 登录后打开含片段的比赛，GIF 提前下载；完整文件的字节数、帧数和时长校验通过后才自动播放，加载期间显示封面。GIF 保持原始比例、完整时长和无限循环；大图及全屏复用同一文件。缓存保留三天，退出比赛和重新加载后继续复用，片段更新或缓存过期再下载；失败可重试，自动播放设置可主动关闭。
5. 从“我的主队”进入球队及管理入口。大名单锁定后按已审核结果展示；头像为空时显示姓名最后一个字。未入选成员以文字区分，继续保留成员管理能力。可编辑阶段通过“加入／移出”调整选择，再保存或提交审核；已锁定名单不能绕过管理审核。
6. “阵容”可选择已保存计划、修改站位、保存或设为默认。系统默认名称简化为“默认阵容”，已有自定义名称保留。正式赛前确认与私人战术草稿仍然分开。
7. 消息中心保留系统、回复、提及和点赞等通知，支持标记已读和打开关联内容；私信入口已退出。个人资料中的昵称、头像、背景和简介按原入口编辑；官方发布在管理平台完成。
8. 更换头像时先选图、手动拖动和缩放裁切，再点保存；界面展示处理和上传状态，失败后可重试。关联球员沿用账号头像时同步更新，独立上传的球员照片保留。
9. 关注管理中按住拖动柄排序，中间项目可以放到最前或最后，贴近列表上下边缘时自动滚动。球员与球队均显示图片，缺少球员图片时使用姓名最后一字。
10. “我的身份”展示球员摘要及主页入口，身份关联在“身份管理”操作。信息管理员同一行显示完整赛事名称和选择框，先显示三场紧凑比赛，开始状态放右侧；“展开全部”有边框、箭头和展开/收起状态。下方直接显示质量分与已录入场次。“评分说明”逐项列出真实规则，绿色加分、红色扣分。
11. 数据页“对阵”直接从晋级图开始，图区域使用边到边的浅色背景，左侧阶段名与右侧比赛中线对齐。锁定名次的队伍填入签位，其余只显示“待定”。八强按 A1–B2、C1–D2、B1–A2、D1–C2，同组分处两个半区；四队、八队的连线及对称结构保留。正式比赛保留真实 ID、队伍和成绩，未发布比赛保持只读，季军赛独立展示。女足当前四组各第一名晋级四强。
12. 申请加入球队时，“位置”与选择框在同一行；下方留言为单行、居中的选填输入框，保留清楚的上下间距。所有入口复用同一份申请表单。

## 安装与运行

使用原主仓锁定依赖，不在迁移中升级框架。需要兼容的 Node.js 和 pnpm。

```powershell
pnpm install --frozen-lockfile
pnpm dev:weapp
pnpm dev:web
pnpm dev:admin
```

网站使用 3000，API 使用 3001。微信可使用 `apps/weapp/.env.beta` 中已有云通道进行本地构建；普通本地模式用 `TARO_APP_API_BASE_URL` 指向已有 API。不要为看小程序而启动 Docker。

后端运行需要真实可用的 PostgreSQL 配置。准备自己的 `DATABASE_URL` 后再执行 `pnpm dev:api`；本项目不会自动启动数据库，也不把已有数据缺失伪装成新空库。没有把旧项目真实数据库口令复制进来。本地媒体默认写到旁边的 `XQ-data/media/posts`，部署时使用明确的持久卷路径。
