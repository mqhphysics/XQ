# 晓球架构与契约

小程序、电脑网站和管理后台使用同一套 API。各端维护自己的界面，公共契约位于 `packages/contracts`。赛程、队伍、赛果和报名以服务端为准，异步任务由 Worker 消费。DTO 是接口定义源，`packages/api-client` 由 OpenAPI 生成。

## 杯赛目录和首页

`CompetitionDefinition` 表示可跨赛季复用的杯赛及组别，`Season` 表示赛季，`Tournament` 表示该杯赛在一个赛季的实例。组织管理员在管理中心新建杯赛草稿，发布赛程后可以将其设为首页赛事。公共目录返回 `defaultTournamentId`，首页返回 `tournament.cupName` 和 `seasonName`。显式赛事链接继续读取指定赛事，默认选择优先采用后台设置。技科杯、绿茵杯及后续杯赛沿用这套目录。

## 组赛、淘汰赛和球员赛程

- 小组榜从已确认的比赛报告计算积分和同分排序。提前出线预览在完整单循环的小组内枚举剩余赛果，采用该杯赛的胜平负和弃权积分。同分时保守估计名次，无法锁定具体名次的队伍保留签位待定。计算量超限或采用跨组比较的特殊赛制，由管理员确认。
- 一、二、四、八组的常规对阵支持每组取一或两队，具体取决于配置和签位数。默认按组顺序交叉配对。淘汰赛尚无正式场次时，数据页可显示只读对阵预览。已排的正式签位可以由后台在规程中配置抽签来源，发布的显式签位优先于默认交叉。
- 小组赛程完整且本组正式赛果和名次确定时，自动填入本组对应的空签位。淘汰赛每一场正式比分确认后，按胜负来源填入下一场对应一侧。未完成确认、未决平局和待裁定结果等待核对。自动填入保留晋级版本和审计，已指定的对阵或开赛、已有报告、锁定阵容的比赛由管理员按既有保护流程处理。
- 球员赛程依据所属队、入队离队时间、适用的锁定报名名单及正式出场证据。首次名单确实晚录入时可覆盖本届更早的比赛。未踢的本队比赛可出现在赛程，个人统计独立从正式参赛依据计算。

## 内容、账号和审计

正式小程序的发帖、回复、转发和私信入口由构建配置关闭。内部候选通过 `XIAOQIU_WEAPP_UGC=1` 开启入口。两端共用后端，审核通过并发布的公开动态可以在正式版阅读。服务端继续校验会话、内容对象、组织、角色和内容审核。正式版的界面开关仅影响交互入口。

公开内容的作者、系统通知的发送标识和后台操作的审计身份是三个不同的字段。AI 代录使用独立账号时，应按赛事或比赛授权录入，报告保留该账号作为操作者，正式审核、发布和管理权限由相应管理员持有。
